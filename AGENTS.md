## Monorepo layout

This is a Bun workspaces monorepo. `apps/web` is a TanStack Start app (Vite + Nitro, file-based routing under `apps/web/src/routes`; `src/routeTree.gen.ts` is generated by the Vite plugin and committed).

- `apps/web` stays thin: routing, root layout/document and wiring only. Routes compose features from `packages/features`.
- `packages/features` and `packages/components` must not import from `@tanstack/react-start`, `@tanstack/react-router` or any other web framework; the app only consumes them. `packages/components` holds the shadcn components and the Tailwind theme.
- `packages/features` holds one folder per feature. A feature can have a `client/` (React UI, entry `@app/features/<feature>/client`) and a `server/` (plain `(Request) => Response` endpoints, entry `@app/features/<feature>/server`). Client and server never import each other, and the server imports no React or components. The feature work happens here.
- Server state on the client goes through TanStack Query. `apps/web/src/router.tsx` creates the `QueryClient` (one per request) and `@tanstack/react-router-ssr-query` provides it; features use `@tanstack/react-query` hooks (`useMutation`, `useQuery`) and never create a client or provider.
- `packages/contracts` holds types shared by client, server and adapters, including the `CaptionSource` port. `packages/teams-cdp` is an adapter that implements it over the Chrome DevTools Protocol; it must not import `@app/features`, `@app/components`, React or a web framework (oxlint enforces this). The captions server must not import the adapter; the app wires it in `apps/web/src/caption-handlers.ts`.
- `packages/transcripts-sqlite` implements the `TranscriptStore` port with Node's built-in `node:sqlite` (Node 22.13+; Bun's runtime does not have it, so run server code with Node). It has the same import limits as `teams-cdp` (oxlint enforces them). Recording runs on the server (`captions/server/recorder.ts`), independent of any browser; the page only follows it.
- `packages/copilot-sdk` implements the `ChatBackend` port with the GitHub Copilot SDK (same import limits as the other adapters, enforced by oxlint). The chat server must not import it; `apps/web/src/chat-handlers.ts` wires it. The SDK stays external in the production build (`apps/web/vite.config.ts`) because it resolves its runtime package at run time; it is a dependency of `apps/web` and of the root package.
- `apps/desktop` is a Tauri shell with no UI of its own: it starts the built web server (`apps/web/.output`) as a bundled Node sidecar and navigates its window to it. Keep the app a normal web server; the shell only supplies `PORT`, `HOST` and `TRANSCRIPTS_DB`. `scripts/prepare-sidecar.mjs` must install the packages the server build leaves external (currently `@github/copilot-sdk`).
