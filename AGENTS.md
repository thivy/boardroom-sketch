# Boardroom Sketch

A Bun workspaces monorepo. `apps/web` is a TanStack Start app (Vite + Nitro, file-based routing under `apps/web/src/routes`; `src/routeTree.gen.ts` is generated by the Vite plugin and committed). `apps/desktop` is an Electron shell around it.

## Commands

Run from the repo root (Bun is pinned in `packageManager`).

- `bun run dev`: the web app. `bun run build` and `bun run start`: the production build.
- `bun run typecheck`: type-aware lint with tsrs, plus the desktop check. `bun run typecheck:tsc` is the `tsc` fallback.
- `bun run lint`, `bun run lint:fix`: oxlint. `bun run fmt`: format. Format only the files you touch, because `fmt:check` fails on older files.
- `bun test`: tests (the repo has none yet).

## Layout and boundaries

Oxlint enforces most of these. Read the skill in the last column before you work in that area; it routes to the right reference.

| Package                                                                 | Holds                                                                                                    | Must not import                                                                       | Skill                    |
| ----------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- | ------------------------ |
| `apps/web`                                                              | Routing, the root layout and wiring only. The only non-route files are `*-handlers.ts` and `storage.ts`. | `node:*`, the Copilot SDK, `@app/contracts` (in route files), feature code            | `project-architecture`   |
| `packages/features`                                                     | One folder per feature, with `client/` and `server/`.                                                    | A web framework, adapters, other features. Client and server never import each other. | `project-architecture`   |
| `packages/ui`                                                           | Styled ui-sdk wrappers, shared layout, the Tailwind theme.                                               | A web framework                                                                       | `ui-sdk`, `design-guide` |
| `packages/contracts`                                                    | Types and ports shared by client, server and adapters.                                                   | Everything else                                                                       | `project-architecture`   |
| `packages/teams-cdp`, `packages/copilot-sdk`, `packages/storage-sqlite` | Adapters that implement the ports.                                                                       | `@app/features`, `@app/ui`, React, a web framework                                    | `project-architecture`   |
| `apps/desktop`                                                          | The Electron shell. It has no UI of its own.                                                             |                                                                                       | `project-architecture`   |

## Rules that apply everywhere

- Server state on the client goes through TanStack Query. Other client state goes in Zustand stores (`react-state` skill). `useState`, `useReducer` and effect hooks are banned in features.
- A feature's server never imports an adapter. The app connects them in `apps/web/src/*-handlers.ts`.
- Server handlers and large stores are split into groups of plain functions that a thin `handlers.ts` or `<store>.ts` composes.
- The meeting graph's rules live in `packages/contracts/src/graph-vocabulary.ts`. Change them there, never in an adapter.

## Skills

Project skills live in `.agents/skills`. Use the one that matches your task:

- `project-architecture`: where code belongs. It routes to references for features, ports and adapters, SQLite stores, the meeting graph and the desktop shell.
- `react-state`, `ui-sdk`, `design-guide`, `vercel-composition-patterns`, `vercel-react-best-practices`, `untangle-codebase`: general guidance.

## ui-sdk

Before using ui-sdk (`@ui-sdk/react`, `@ui-sdk/core`), follow the ui-sdk skill if it is installed, and read `node_modules/@ui-sdk/react/docs/llms.txt`. To build a new component, also search `node_modules/@ui-sdk/react/docs/core.md` by heading, and read `rendering.md` next to it.
