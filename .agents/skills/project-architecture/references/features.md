# Feature structure

`packages/features` holds one folder per feature. The feature work happens here. `apps/web` only routes and wires.

## Layout

- A feature can have a `client/` (React UI, entry `@app/features/<feature>/client`) and a `server/` (plain `(Request) => Response` endpoints, entry `@app/features/<feature>/server`). Add both entries to the `exports` of `packages/features/package.json`.
- Client and server never import each other. The server imports no React or components.
- Features never import each other. Code that more than one feature needs lives in `packages/features/src/shared/{client,server}` (the JSON/SSE helpers for endpoints, the transcript export format, the client's `request` helper). The same import limits apply to it.
- `packages/features` and `packages/ui` must not import `@tanstack/react-start`, `@tanstack/react-router` or any other web framework. The app only consumes them. `packages/ui` holds the styled ui-sdk wrappers, shared layout and the Tailwind theme.

## Server handlers

`handlers.ts` only composes. Each endpoint group is a file of plain exported functions (`*-handlers.ts`, such as `transcript-handlers.ts`) that take the `Request` and what they need. `createXHandlers(...)` returns one `(Request) => Response` per endpoint by calling them. Use this for every feature (captions, chat, graph and workspaces all do).

Endpoints that change something call `rejectNonJson` first. Use the helpers in `shared/server/http.ts` (`json`, `readJson`, `idParam`, `queryParam`).

## Client state

- Server state goes through TanStack Query. `apps/web/src/router.tsx` creates the `QueryClient` (one per request) and `@tanstack/react-router-ssr-query` provides it. Features use `useQuery` and `useMutation` and never create a client or provider. Call the API with `request` and `jsonRequest` from `shared/client/api-request.ts`.
- Other client state (selections, drafts, streams, view filters) lives in Zustand stores, one `*-store.ts` per page or flow in the feature's `client/`, built with `createStore` from `shared/client/create-store.ts`. Follow the `react-state` skill. State stays inside the store, actions are exported plain functions (never selected from the store), components use atomic selectors, and the page calls `reset` when it unmounts. Use `whileUsed` and `onUnused` for timers and streams.
- `useState`, `useReducer` and effect hooks are banned in features (oxlint `no-restricted-imports` on `react`, which also rejects `import React` and `import * as React`). Keep DOM refs in `useRef` and external subscriptions in `useSyncExternalStore`. The generated shadcn files in `packages/ui/src/components` are exempt.
- The sidebar in `packages/ui` keeps its open state in a per-provider store (`packages/ui/src/lib/sidebar-store.ts`), because a shared singleton would leak between server requests.

## Wiring in apps/web

- Routes compose features. A feature that needs a router link takes it as a prop (the app shell takes `navItems` with a `link` element, and the workspaces pages take `openLink` and `backLink`), so features never import the router.
- A page can offer a slot for another feature. The transcripts page has an `actions` slot that the graph feature fills in `apps/web/src/routes/transcripts.tsx`, so the two features never import each other.
- A feature's server is connected to its adapters in one `apps/web/src/*-handlers.ts` file. Shared stores are opened once in `apps/web/src/storage.ts`. API routes in `apps/web/src/routes/api` just call those handlers.
- `src/routeTree.gen.ts` is generated by the Vite plugin when the dev server or a build runs. Commit it.

## Example: workspaces

`packages/features/src/workspaces` is the smallest complete feature: a landing page, a page per workspace and an editable title. The title autosaves from `title-editor.ts` with a debounced `PATCH` that still runs if the person leaves the page, and shows no save status. The `WorkspaceStore` port is in `packages/contracts`, and `workspacesSqlite` is in `packages/storage-sqlite`.
